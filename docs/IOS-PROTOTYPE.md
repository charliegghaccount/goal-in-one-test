# Goal In One — Capacitor iOS prototype

This experiment lives on **feature/capacitor-ios-prototype**. It does not merge into main or deploy over the existing GitHub Pages game.

## Run on a Mac / iPhone 16 Pro

Install Node 22.12+ (Node 24 recommended) and Xcode 26 or a newer release supported by Capacitor 8. Install the required iOS SDK/device support in Xcode. Initial dependency installation and Swift package resolution need internet access; the installed game does not.

```sh
git fetch origin
git switch feature/capacitor-ios-prototype
npm ci
npm run ios:sync
npm run ios:check
npm run ios:open
```

The project is `ios/App/App.xcodeproj`, scheme **App**, using Swift Package Manager (no CocoaPods step). In Xcode's App target → Signing & Capabilities, choose your Apple development team and enable automatic signing. The provisional identifier is `com.goalinone.game`. Before publication, change it in **both** `capacitor.config.ts` and Xcode's bundle identifier for Debug/Release. Keep it stable during update/persistence tests. App display name is Goal In One; deployment target is iOS 15. Both landscape directions are configured for iPhone and iPad; iPad requires full screen. Status bar is hidden. The icon uses the existing wood/football artwork; launch is a plain matching brown surface, without an artificial loading delay.

Connect/unlock the phone, trust the Mac, enable Settings → Privacy & Security → Developer Mode if prompted, select the iPhone in Xcode and press Run. A personal team can be used for a development install with Apple's account/device limitations. No distribution certificate or App Store submission is prepared here.

For simulator testing, select an installed iPhone simulator and Run. Linux cannot compile or execute this project; `cap sync` is not an Xcode build.

After every game-source change run `npm run ios:sync` before building again. `npm run ios:run` synchronizes and invokes Capacitor's device runner. Normal browser commands remain `npm run dev`, `npm run build`, and `npm run build:pages`. The native command uses `--base=./ --outDir=dist-native`, independently of the Pages `/goal-in-one-test/` base. Generated web copies are intentionally ignored by Git and regenerated by sync.

## What changed / audit

The existing Vite/TypeScript/Matter.js architecture is retained. The project already had fixed-step physics, pointer capture, touch/pinch separation, responsive safe-area padding, bounded particles, a DPR-aware Canvas, static level definitions and locally bundled art/MP3s. There was no demonstrated need for a physics or renderer rewrite. No level or camera definitions changed.

Capacitor **8.6.0** wraps the local bundle, with App **8.1.2** for lifecycle and Preferences **8.0.1** for a native save backup. There is no `server.url`, CDN, remote font, ad, payment or analytics dependency for the game. The pre-existing developer-only Studio “Test in Godot” opens an external preview and intentionally needs a network connection; that optional comparison tool is preserved, not included in offline gameplay. The native copy is hash-checked against the build by `npm run ios:check`, including four supplied MP3s. Developer-only tooling and Pages deployment remain available in the browser. In a native debug Web Inspector, opening `location.search="?dev=1&editor=1"` exposes the existing Studio without changing the app origin.

A small bootstrap restores native backup data before importing the game, so startup cannot save an empty default over a not-yet-loaded native save. Existing `goal-in-one:*` localStorage keys remain canonical and retain their formats, including best scores, stable campaign revisions, audio/physics settings and Studio drafts. Only missing local keys are restored; existing values win over an older backup. Writes mirror to one app-scoped Preferences snapshot, with a bounded latest-write queue rather than unbounded pending snapshots. Failures display a recovery warning; a failed initial restore does not reset data and offers Retry.

The native Preferences UserDefaults access reason is declared as CA92.1 in `PrivacyInfo.xcprivacy`. The declaration is a prototype starting point, not an App Store privacy review. A warm foreground retains the current scene; cold launch returns to the menu with progress/settings/drafts restored, rather than restoring an in-flight shot snapshot. Storage is per app installation/origin; routine updates should retain it if the app ID and origin stay unchanged. Uninstalling erases local data. Safari/Pages saves are in a different sandbox and are not automatically transferred to this app. Campaign JSON export/import remains useful; native file downloads/share-sheet behaviour needs phone testing before relying on it as a backup workflow. Studio itself is retained rather than redesigned for small screens.

Native app-state, pause/resume and web visibility/page lifecycle events gate simulation, cancel dragging, stop/suspend audio, clear fixed-step accumulation and show the existing pause menu when needed. Foregrounding retains the paused scene; the player resumes explicitly. No elapsed background time is simulated. Audio resumes from an ordinary user gesture. Scene-based interruption delivery and real audio-route interruptions still need testing in WKWebView.

## Separate announcer option

Settings → **ANNOUNCER: OFF / ON** is saved independently of the sound-effects mute. It is **off by default**, including legacy saves with sound enabled. Voice MP3s are not fetched/decoded while the option is off. Enabling it keeps the existing four supplied recordings and exact one-shot/star/par priority rules. Disabling or muting cancels active/pending lines; sound effects remain available when voices are off. Three-star multi-shot goals still use the regular jingle.

## Phone acceptance checklist

- Cold launch, all four UI screens, 25-tile chapter navigation, restart, pause and completion in both landscape directions. Check notch, corners, home indicator, readable text and comfortable targets.
- Try short/full-power mouse-equivalent finger drags, edge drags, repeated mid-flight kicks, more than ten kicks, explore/pinch/zoom and Return to Ball. No scrolling, duplicate kick or gesture handoff errors should occur.
- Play representative compact/tall/scrolling/mechanism levels (1, 5, 9, 42, 53, 54, 58, 60). Inspect springs, fans, moving gates, particles and goal entry.
- Start with sound effects enabled and announcer OFF. Enable announcements, verify one-/two-/one-star rules, mute, restart during a line, connect/disconnect headphones and interrupt with Siri/calls.
- Background while aiming, rolling and scoring; wait 30 seconds; foreground. Verify cancelled aim, paused simulation, no catch-up jump and no stale speech. Rotate while paused.
- Score, change settings, save a Studio draft; close/reopen. Test ordinary reinstall-as-update **without deleting the app**, plus termination immediately and several seconds after saving. Confirm scores, revisions, settings and drafts persist.
- Enable Airplane Mode, force-quit, cold-launch and complete a level. No network should be necessary, including voice playback after enabling it.
- Use Xcode Instruments / Safari Web Inspector for at least 15–30 minutes, including repeated restarts, moving-obstacle levels and thermal stress. Record device/OS, frame pacing, allocations and crashes. A commercial 60-FPS claim requires this hardware test.

## Diagnostics and measured evidence

Run dev mode at `/?dev=1&perf=1`; inspect `window.__goalPerformance.summary()` in the console. This bounded sampler reports up to 600 frame gaps, fixed-step CPU time, total frame work (render + HUD + physics), long frames, recent level load durations and JS heap where supported. Estimate non-physics render/HUD work by subtracting physics from frame work. Production builds disable the sampler; no telemetry is transmitted.

The [measured desktop sample](ios-evidence/desktop-profile.json) is **Linux headless Chromium, not iOS**, at 932×430 on level 60, with concurrent tests running: 600 samples, mean frame gap 16.666 ms, mean physics work 0.148 ms, total frame work 1.798 ms, 0 gaps above 33.34 ms, observed level load 8.6 ms, JS heap approximately 8.74 MB. Observed interactive startup was 431.5 ms. This is a short desktop feasibility sample, not a long-session, GPU, thermal, simulator or iPhone benchmark.

## Feasibility assessment

**Recommendation B: continue with TypeScript/Capacitor, with targeted validation and hardening before a commercial release.** Current code and desktop measurements reveal no reason to restart the Godot migration. Native compilation, device frame pacing, storage durability and interruption delivery are still unverified on hardware.

100–500 authored levels and additional mechanics fit this data-driven renderer in principle, but full campaign JSON and synchronous Studio storage must be measured with realistic large campaigns before choosing per-design files/IndexedDB or another storage strategy. Avoid a speculative database migration now. Level sharing would need a trusted import/service boundary plus native file/share integration. IAP and ads are possible via native plugins, but StoreKit/Play Billing, consent/privacy, lifecycle and SDK frame costs are separate untested work; none is implemented. Android requires adding/testing its own Capacitor platform. The current prototype alone does not establish App Store readiness, commercial performance or cross-platform parity.

## Automated validation

- 627 runtime tests passed.
- The complete 62-case browser suite passed, including actual drag completions of all 60 levels, touch/camera regressions, Studio and all announcer conditions with explicit opt-in fixtures.
- 11 final native/audio checks passed after adding WebKit interrupted-state recovery and edge-touch coverage at 1280×720, 932×430, 844×390 and 740×360 (DPR 2). There are 63 distinct browser cases across these runs.
- Native production build, Capacitor sync, byte-identical offline asset copy check and normal Pages production build passed. Xcode project structure, plist and storyboard XML parse successfully.
- Mock-native restoration/lifecycle tests are not native SDK execution. The offline test serves only bundled files through Playwright routing with Chromium offline, using a secure synthetic origin; it is not an iOS Simulator test.

See [validation results](ios-evidence/validation.json) for the exact build/test scope. iOS compilation, Simulator and physical iPhone execution are explicitly **not performed** in this Linux environment.
